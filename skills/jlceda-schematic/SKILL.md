# 嘉立创专业版原理图工程流程

先读 [工具与安全边界](references/tools.md) 和 [布局规范](references/layout-rules.json)。这些文件与本 Skill 一起复制即可；不要引用某个历史项目的绝对路径、UUID、器件编号或页数。

## 输入与交付

从用户文件、数据手册和工程读取：电源域、模块职责、器件型号、真实引脚定义、连接关系、板级接口、设计约束。能由文件/SDK获得的信息不要反问用户。电路意图存在真正歧义时再问；不得把近似型号、通用符号借用或推断连接伪装成已确认。

交付可编辑原生工程、矢量PDF、核验记录；保留源工程。报告清楚区分原理图正确性、PCB布局布线完成度、硬件实测状态。不能因DRC通过就声称可投板。

## 1. 建立目标与基线

1. `jlc_status` 确认唯一已认证编辑器、当前工程和图页、写入开关及不确定状态。当前页不是目标页时，在EDA明确打开正确图页后再操作。
2. 新设计使用 `jlc_create_project`；已有设计先在EDA复制为新工程，保留原始epro2。切换前手动保存所有正在编辑的文档：官方 `openProject` 明确警告可能丢失未保存数据，原生导出备份不是对未提交GUI编辑的事务保证。
3. 读取 `jlc_snapshot`、`jlc_netlist`、`jlc_drc`，保存基线。已有PCB时另外导出PCB网表与元件/封装信息；本MCP不写PCB。
4. 默认只读。实际写入需在客户端环境明确设置 `JLCEDA_ENABLE_WRITES=1` 后重启MCP；只给本工具扩展启用外部交互权限。

## 2. 先设计模块，再放器件

- 一页一组相关功能；主信号从左到右，参考/控制独立通道，电源与GND就近。
- 先定模块输入/输出、器件方向、反馈/采样/定时/高电流闭环位置，再确定坐标。模块放不下时扩大空间或移动器件，不要先围着IC兜线补救。
- 官方图符优先，允许整体旋转/镜像以匹配真实引脚顺序；不为视觉美观重画符号或重编号引脚。
- 反馈、补偿、定时RC、差分对、采样回路等解释电路拓扑的连接保留真实线；跨模块信号、同侧输出可用短原生端口。禁止把全部连接藏成网名。
- 原理图位置不是PCB位置；短原理图导线不证明短PCB回路。

## 3. 真实器件与两阶段布线

1. `jlc_search_devices` 查正式库DEVICE；核对厂家型号、供应商编码、引脚表、封装及数据手册。搜索命中不等于型号合适；无精确型号则明确说明差异，不偷偷替换。
2. 第一批计划只创建器件与注释。`component.create` 必须给真实库UUID/libraryUuid、设计ator、坐标、真实旋转/镜像。器件由SDK关联正式符号与封装，不自行构造符号多边形。
3. `jlc_plan` 返回无错误的计划后才 `jlc_apply` 一次。读取实际SDK引脚坐标、引脚号，再生成导线计划。创建器件与连接新器件不能同批猜坐标。
4. 输入坐标统一为屏幕坐标：+Y向下；适配器在SDK边界只反转一次。SCH单位为10mil。保留半格等原始数值，不能取整吸附到自己估计的网格。
5. 旋转/镜像既有器件需分阶段：显式删除接触其引脚的旧线/端口，单独完成变换，再回读新引脚坐标后布线。普通平移同样必须处理原有线端，不能留下悬空旧线。
6. 移动器件必须保留所有采购字段、自定义字段和空的Supplier Part；不能用SDK modify的缺省值覆盖它们。

## 4. 原生电气对象

- GND是 `marker.create` 的 `Ground`，电源是 `Power` 等正式类型；同名文字不是地线。
- 端口是原生 `IN/OUT/BI`；网名完全一致且清晰可读。
- 导线使用 `wire.create`：正交非零分段，端点使用真实pin坐标。分支须形成真实公共节点。命名一次即可，避免同一网络重复自动标注。
- NC用 `pin.nc` 设置真实引脚NoConnected并回读；不能画X替代。接触导线或端口的引脚不能标NC。
- 只删除计划中明确列出的原生wire/marker IDs；禁止整页清空或删除无关器件。
- 文字、模块框仅为注释，不承载电气语义。当前SDK有已知删除文字的导出缓存问题，本工具不提供文字删除/改写，不能把画布消失当作文件已删除。

## 5. 计划与失败处理

`jlc_plan → 审查操作/错误/警告 → jlc_apply(planId)`。计划绑定工程、页、编辑器连接会话和完整快照；过期、状态变化、断线重连后重新规划。一次apply尝试消耗计划，即使预检失败也不能重用。

MCP在变更前下载原生备份并落盘日志。修改是串行、非事务的：出错可能已经完成一部分。超时不表示编辑器停止；严禁自动重试、补发同一计划或盲目重新创建器件。不确定状态会锁住后续写入。等待编辑器静止、检查实际图面和日志，需要时从备份恢复；确认现场后再重启MCP并读取新快照。

写入期间不要让人或另一自动化同时操作编辑器。只允许一个MCP进程占用同一个桥接端口；后接入编辑器不能替换正在工作的连接。

## 6. 验收

- 计划检查：异网端点/T接触、重叠与交叉；NC接触；重复编号；非法删除；变换分阶段；通常导线路径不超过两折。警告不可当成电气通过证明。
- SDK回读：器件/引脚数量、真实位置方向、NC、导线覆盖与网名；不能只信创建返回ID。
- 电气：PADS网表按 `REF.pin` 集合比较。仅排版时要求每个命名网络成员与基线相同；设计变更时逐网对照明确的目标连接表，不只比较数量。网络自动名变化也须解释，不擅自视为相同。
- 原生DRC：记录具体错误、警告和理由。现有警告不通过隐藏、改测试文字或造假统计来消除。
- 图面：导出原生PDF后逐页看实际符号、网名、值、模块文字、短竖线标签；检查遮挡、重叠、分支歧义、主信号方向。程序没有可靠的官方符号本体边框，所以不能自动声称零穿器件或文字零重叠。
- 持久性：将最终epro2导入另一个新工程，回读器件、网表、NC，再看原生导出。不直接覆盖唯一副本。版本升级/迁移机器后重新执行通用RC示例，而不是假定兼容。
- 输出核验记录标注应用/SDK版本、实际运行的场景、未覆盖边界。布局数值是项目规范，不宣称IEC认证。

## 能力边界

本 Skill + MCP 支持原生原理图对象与受控编辑，不是电路正确性证明器、任意电路自动布局器、仿真器或PCB布线器。需要数据手册、电气意图和实际视觉审查。当前实现没有公开任意JS执行、通用底层API转发或自动更改原始epru电气记录的接口。
